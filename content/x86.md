# Registers and Flags

x86-64 (AMD64 / Intel 64) extends 32-bit IA-32 to 64-bit registers and addresses while staying backward compatible.

## General-purpose registers

| 64-bit | 32 | 16 | 8 low | 8 high | Conventional role |
|---|---|---|---|---|---|
| RAX | EAX | AX | AL | AH | accumulator, **return value** |
| RBX | EBX | BX | BL | BH | callee-saved base |
| RCX | ECX | CX | CL | CH | counter (`rep`, shifts by CL); arg 4 SysV / **arg 1 Win64** |
| RDX | EDX | DX | DL | DH | arg 3 SysV / arg 2 Win64; high half of mul/div |
| RSI | ESI | SI | SIL | — | source index; **arg 2 SysV** |
| RDI | EDI | DI | DIL | — | destination index; **arg 1 SysV** |
| RBP | EBP | BP | BPL | — | frame pointer (optional) |
| RSP | ESP | SP | SPL | — | **stack pointer** |
| R8–R15 | R8D–R15D | R8W–R15W | R8B–R15B | — | R8/R9 = args 5/6 SysV, args 3/4 Win64 |

Special registers:
- **RIP**: instruction pointer. It can't be written directly, but **RIP-relative addressing** (`lea rax, [rip+0x2f1a]`) is everywhere in position-independent code.
- **RFLAGS**: status flags.
- **Segment registers**: CS, SS, DS and ES are mostly flat in 64-bit mode. **FS** and **GS** hold bases used for thread-local storage. On Linux, `fs:[0x28]` is the stack canary. On Windows x64, `gs:[0x30]` points to the TEB and `gs:[0x60]` to the PEB (on 32-bit Windows that's `fs:[0x30]`).
- **Control registers** CR0 (PG, WP…), CR2 (page-fault address), CR3 (page-table base), CR4 (SMEP, SMAP, PAE…).
- **Debug registers** DR0–DR3 (hardware breakpoint addresses), DR6 (status), DR7 (control).
- **MSRs** (model-specific registers), read with `rdmsr`/`wrmsr`, for example `IA32_LSTAR` (the syscall entry point) and `IA32_EFER` (long mode, NXE).
- **SIMD**: XMM0–15 (128-bit, SSE), YMM (256-bit, AVX), ZMM0–31 (512-bit, AVX-512), plus mask registers k0–k7.

> [!warn] **The 32-bit write rule**: writing a 32-bit register zero-extends into the full 64-bit register (`mov eax, 1` clears bits 32–63 of RAX). Writing an 8- or 16-bit register leaves the other bits unchanged. Compilers therefore prefer `xor eax, eax` (shorter, and still zeroes all of RAX). Try it in the Lab's Register view.

## RFLAGS

| Flag | Bit | Set when |
|---|---|---|
| CF carry | 0 | unsigned overflow / borrow |
| PF parity | 2 | low byte of the result has an even number of 1 bits |
| AF adjust | 4 | carry out of bit 3 (BCD) |
| ZF zero | 6 | result is zero |
| SF sign | 7 | MSB of the result is 1 |
| TF trap | 8 | single-step (debuggers) |
| IF interrupt | 9 | interrupts enabled |
| DF direction | 10 | string ops go downward |
| OF overflow | 11 | signed overflow |

`cmp a, b` computes `a − b` and only sets flags. `test a, b` computes `a & b` and only sets flags. `test eax, eax` is the idiomatic "is EAX zero?" check.

# Syntax, Operands and Addressing Modes

## Intel vs AT&T syntax

| | Intel (IDA, Ghidra, x64dbg, MASM/NASM) | AT&T (GNU as, objdump default, GDB default) |
|---|---|---|
| Operand order | `mov dst, src` | `mov src, dst` |
| Registers | `rax` | `%rax` |
| Immediates | `5` | `$5` |
| Size | from operands or `qword ptr` | suffix: `movb/w/l/q` |
| Memory | `[rbx + rcx*8 + 0x10]` | `0x10(%rbx,%rcx,8)` |

> [!tip] Switch GDB or objdump to Intel syntax with `set disassembly-flavor intel` or `objdump -d -M intel`. Put the GDB setting in `~/.gdbinit`.

## Addressing modes
General form: `[base + index*scale + displacement]`, with scale ∈ {1, 2, 4, 8}.

```asm
mov eax, [rbx]                 ; *(int*)rbx
mov eax, [rbx+8]               ; struct field at offset 8
mov eax, [rbx+rcx*4]           ; int array: arr[i]
mov rax, [rbx+rcx*8+0x10]      ; array of pointers inside a struct
lea rax, [rip+0x2e5a]          ; address of a global (PIC)
mov rax, qword ptr gs:[0x60]   ; Windows PEB
```

**`lea` computes an address but doesn't access memory.** Compilers use it for arithmetic: `lea eax, [rdi+rdi*2]` is `eax = rdi*3`, and `lea eax, [rdi+rsi+5]` is a three-operand add.

## Instruction encoding (brief)
`[legacy prefixes] [REX] opcode [ModR/M] [SIB] [displacement] [immediate]`, at most 15 bytes.
- **REX** prefix `0x40–0x4F`: W (64-bit operand), R/X/B (extend register fields to reach R8–R15). `48` in front of an opcode usually means a 64-bit operation: `48 89 e5` = `mov rbp, rsp`.
- **VEX/EVEX** prefixes encode AVX and AVX-512.
- Common bytes worth recognising: `55` push rbp, `C3` ret, `CC` int3, `90` nop, `E8 rel32` call, `E9 rel32` jmp, `EB rel8` short jmp, `74/75` je/jne short, `0F 05` syscall, `FF 15` call [rip+x] (Windows IAT calls), `F3 0F 1E FA` endbr64 (CET/IBT landing pad).

# Core Instruction Set

## Data movement
| Instruction | Effect |
|---|---|
| `mov dst, src` | copy (no flags) |
| `movzx` / `movsx` / `movsxd` | zero / sign extend |
| `lea dst, [mem]` | address computation |
| `push` / `pop` | RSP −= 8 then store / load then RSP += 8 |
| `xchg`, `cmpxchg`, `xadd` | atomics (with the `lock` prefix) |
| `cmovCC` | conditional move (branchless code) |
| `setCC r8` | set a byte to 0/1 from the flags (boolean results) |
| `bswap` | reverse byte order (endianness conversion) |

## Arithmetic and logic
`add, sub, inc, dec, neg, adc, sbb, imul, mul, idiv, div, and, or, xor, not, shl/sal, shr, sar, rol, ror, bt/bts/btr, popcnt, lzcnt, tzcnt`.

- `mul r64`: RDX:RAX = RAX × r64 (unsigned). `imul` has 1-, 2- and 3-operand forms.
- `div r64`: divides RDX:RAX by r64, quotient in RAX and remainder in RDX. Before a signed `idiv`, compilers emit `cqo`/`cdq` to sign-extend RAX into RDX.
- `sbb eax, eax` gives 0 or −1 depending on CF, a classic branchless idiom.

## Control flow
- `jmp target`; `call target` pushes the return address and jumps; `ret` pops into RIP.
- Conditional jumps after `cmp a, b`:

| Condition | Unsigned | Signed |
|---|---|---|
| a == b | `je` / `jz` | `je` |
| a != b | `jne` / `jnz` | `jne` |
| a < b | `jb` / `jnae` / `jc` | `jl` / `jnge` |
| a <= b | `jbe` / `jna` | `jle` / `jng` |
| a > b | `ja` / `jnbe` | `jg` / `jnle` |
| a >= b | `jae` / `jnb` / `jnc` | `jge` / `jnl` |

> [!tip] Signedness hides in the jump mnemonic. **Above/Below = unsigned; Greater/Less = signed.** Many integer-overflow bugs come down to a signed comparison (`jl`) guarding a length that's later used as unsigned.

## String instructions
`movs, stos, lods, scas, cmps` with the `rep`/`repe`/`repne` prefixes, using RSI/RDI/RCX. `rep stosb` is memset; `rep movsb` is memcpy; `repne scasb` is the classic inline strlen.

## System
`syscall`/`sysret` (64-bit system calls), `int 0x80` (legacy 32-bit Linux syscalls; still works on many 64-bit kernels but uses the 32-bit ABI), `cpuid`, `rdtsc` (timestamp counter, used in anti-debug timing), `hlt`, `ud2` (deliberate invalid opcode, emitted after `__builtin_unreachable`/assert failures).

# Calling Conventions and the Stack

The stack grows **down** (toward lower addresses). `push` decrements RSP; `call` pushes the return address.

## System V AMD64 ABI (Linux, macOS, BSD)
- Integer/pointer args: **RDI, RSI, RDX, RCX, R8, R9**, then the stack.
- Floating-point args: XMM0–XMM7.
- Return: RAX (plus RDX for 128-bit); XMM0 for floating point.
- **Callee-saved**: RBX, RBP, R12–R15 (and RSP). Everything else is caller-saved (volatile).
- RSP must be **16-byte aligned at the call instruction** (so at function entry RSP ≡ 8 mod 16).
- **Red zone**: 128 bytes below RSP that leaf functions may use without adjusting RSP. Kernel code compiles with `-mno-red-zone`.
- Variadic functions: AL = number of vector registers used (that's why you see `xor eax, eax` before calls to `printf`).

## Microsoft x64 (Windows)
- Args: **RCX, RDX, R8, R9**, then the stack. FP args in XMM0–3, in the *same positions* as integer ones.
- The caller always reserves **32 bytes of shadow space** (home space) above the return address, even for functions with fewer arguments.
- Callee-saved: RBX, RBP, RDI, **RSI**, R12–R15, XMM6–XMM15.
- Return in RAX/XMM0. No red zone.
- Unwinding uses table-driven metadata (the `.pdata`/`.xdata` sections), not frame pointers.

## A typical frame

```asm
func:
    push  rbp
    mov   rbp, rsp
    sub   rsp, 0x30          ; locals
    mov   [rbp-0x14], edi    ; spill arg1 (unoptimised code)
    ...
    leave                    ; mov rsp, rbp ; pop rbp
    ret
```

```text
higher addresses
[rbp+0x10]  stack-passed args (SysV 7th+ arg)
[rbp+0x08]  return address
[rbp+0x00]  saved RBP
[rbp-0x08]  locals / canary
...          ← RSP
lower addresses
```

> [!note] Optimised code (`-O2`) often skips the frame pointer (`-fomit-frame-pointer`) and addresses locals relative to RSP. Arguments stay in registers and are never spilled. Learn to read both styles.

## Linux x86-64 syscalls
`syscall` with the number in **RAX** and args in **RDI, RSI, RDX, R10, R8, R9**. R10 replaces RCX because `syscall` clobbers RCX (saved RIP) and R11 (saved RFLAGS). Return value in RAX; −4095…−1 means `-errno`.

| # | Name |
|---|---|
| 0 | read |
| 1 | write |
| 2 | open |
| 3 | close |
| 9 | mmap |
| 10 | mprotect |
| 57 / 59 | fork / execve |
| 60 | exit |
| 231 | exit_group |

```asm
; write(1, msg, 14); exit(0)
mov  eax, 1
mov  edi, 1
lea  rsi, [rip+msg]
mov  edx, 14
syscall
mov  eax, 60
xor  edi, edi
syscall
```

Windows syscall numbers change between builds. User code calls `ntdll.dll` stubs (`mov r10, rcx; mov eax, SSN; syscall`). Malware sometimes performs "direct syscalls" to bypass user-mode EDR hooks.

# Recognising Compiler Idioms

Decompilers are good, but you'll still read raw assembly when they fail: obfuscation, hand-written assembly, bootloaders, shellcode.

## Control structures

```asm
; if (x > 10) foo(); else bar();      (x signed in edi)
cmp   edi, 10
jle   .else
call  foo
jmp   .end
.else:
call  bar
.end:
```

```asm
; for (i = 0; i < n; i++) sum += a[i];
xor   eax, eax          ; sum
xor   ecx, ecx          ; i
.loop:
cmp   rcx, rsi
jge   .done
add   eax, [rdi+rcx*4]
inc   rcx
jmp   .loop
.done:
```

- **Switch statements** compile to a **jump table**: bound check, then `jmp [table+reg*8]` or, in PIC, `movsxd rax, [rdx+rax*4]; add rax, rdx; jmp rax` (a table of relative offsets).
- **Loop inversion**: compilers check the condition once before the loop and then at the bottom (`do { } while`).
- **Tail calls**: a `jmp` to another function instead of `call` + `ret`.

## Data structures
- **Struct access**: constant offsets from one base register (`[rdi+0x18]`, `[rdi+0x20]`). Create a struct type in Ghidra or IDA and apply it.
- **Arrays**: base + index × element size.
- **C++ virtual calls**: `mov rax, [rdi]` (vtable pointer at offset 0 of the object), then `call [rax+0x18]` (the fourth virtual method, at 8 bytes per slot). RDI/RCX is `this`.
- **Strings on the stack**: a run of `mov dword ptr [rsp+..], 0x6c6c6548` immediates ("Hell" in little-endian). Malware uses this to hide strings ("stack strings").

## Optimisation patterns
| Pattern | Meaning |
|---|---|
| `xor eax, eax` | eax = 0 |
| `test eax, eax / jz` | if (eax == 0) |
| `lea eax, [rdi+rdi*4]` | eax = rdi × 5 |
| `imul` by a magic number + `shr`/`sar` | division by a constant |
| `and eax, 0x1f` / `cmp ... ja` | bounds check before a switch |
| `cmovge`, `setl` | branchless conditional |
| `sar eax, 31` | 0 or −1 depending on sign |
| `endbr64` at a function start | Intel CET indirect-branch target |
| `nop word ptr cs:[rax+rax]` | alignment padding (multi-byte NOP) |

## SIMD in disassembly
`memcpy`, `strlen` and string compares are often vectorised: `movdqu`, `pcmpeqb`, `pmovmskb`, `vpbroadcastb`. Crypto: `aesenc`/`aesdec` (AES-NI), `pclmulqdq` (GCM), `sha256rnds2`. Seeing AES-NI instructions immediately tells you which algorithm you're looking at.

# Writing and Testing x86-64 Code

A minimal Linux program with NASM:

```asm
; hello.asm  —  nasm -f elf64 hello.asm && ld -o hello hello.o
section .rodata
msg: db "Hello, metal!", 10
len equ $ - msg

section .text
global _start
_start:
    mov  eax, 1          ; write
    mov  edi, 1          ; stdout
    lea  rsi, [rel msg]
    mov  edx, len
    syscall
    mov  eax, 60         ; exit
    xor  edi, edi
    syscall
```

## Learning workflow
1. Write small C functions and compile them at different optimisation levels: `gcc -O0 -S -masm=intel f.c`, then `-O2`.
2. Use **Compiler Explorer** (godbolt.org) to see the C ↔ asm mapping, colour-coded, across compilers and architectures.
3. Step through in GDB with `layout asm`/`layout regs`, or `si`/`ni` with pwndbg/GEF.
4. Read real binaries in Ghidra with the decompiler side by side.

> [!lab] Exercise: compile `int f(int x){ return x/7; }` at `-O2`. You'll see `imul` by `0x92492493` followed by shifts. That's the magic-number division idiom from the Foundations module.

## Shellcode notes
- It must be position-independent: use RIP-relative addressing, or the `call`/`pop` trick to find its own address.
- It must avoid bad bytes (often `00`, `0a`, `0d`): use `xor eax,eax; mov al, 59` instead of `mov eax, 59`, and push strings in pieces.
- `execve("/bin/sh")` shellcode: set RDI → "/bin//sh\0", RSI = RDX = 0, RAX = 59, `syscall`.
- Tooling: `pwntools` (`asm()`, `shellcraft`), `msfvenom` and `nasm` to build; `scdbg`, `speakeasy`, `qiling` or a debugger to analyse.
